# 1. Overview & Use Cases

## 1.1 What is Amazon S3?

Amazon S3 (Simple Storage Service) is an object storage service provided by AWS. It is designed to store and retrieve any amount of data from anywhere over the internet.

Unlike EC2 or EBS, S3 stores data as **objects** inside **buckets**.

S3 is highly durable (99.999999999% durability - 11 nines), scalable, and managed by AWS.

---

## 1.2 Why Use S3?

Organizations use S3 because it provides:

- Unlimited storage capacity.
- High durability.
- High availability.
- Easy integration with AWS services.
- Secure data storage.
- Low maintenance.

---

## 1.3 Common Use Cases

- Store images and videos.
- Backup and archive data.
- Host static websites.
- Store application logs.
- Store documents and PDFs.
- Data lakes for analytics.
- Software downloads.

---

# 2. Buckets

## 2.1 What is a Bucket?

A Bucket is a container used to store objects in Amazon S3.

Before uploading any file, a bucket must be created.

Example:

```
Bucket
│
├── images/
├── documents/
├── backups/
└── videos/
```

---

## 2.2 Bucket Naming Rules

- Bucket names must be globally unique.
- Only lowercase letters, numbers, and hyphens (-) are allowed.
- Bucket names cannot contain spaces.
- Once created, the bucket name cannot be changed.

Example:

```
my-company-backups
```

---

# 3. Objects

## 3.1 What is an Object?

An Object is the actual file stored inside a bucket.

Each object consists of:

- Data (file)
- Key (file name/path)
- Metadata

Example:

```
Bucket

images/
    logo.png

documents/
    notes.pdf
```

Here,

- Bucket = Storage container
- Object = logo.png / notes.pdf

---

# 4. Bucket Policy

A Bucket Policy is a JSON document used to control access to an S3 bucket.

It specifies:

- Who can access the bucket.
- What actions are allowed.
- Which resources are affected.

Example:

Allow everyone to read files from a static website bucket.

```json
{
  "Effect": "Allow",
  "Principal": "*",
  "Action": "s3:GetObject",
  "Resource": "arn:aws:s3:::my-bucket/*"
}
```

Bucket Policies are commonly used for:

- Public websites.
- Cross-account access.
- Restricting access.

---

# 5. Versioning

Versioning allows multiple versions of the same object to be stored.

Example:

```
resume.pdf (Version 1)

↓

resume.pdf (Version 2)

↓

resume.pdf (Version 3)
```

Advantages:

- Recover deleted files.
- Restore previous versions.
- Protect against accidental overwrites.

Once enabled, Versioning cannot be completely disabled (only suspended).

---

# 6. Replication

Replication automatically copies objects from one bucket to another.

Types:

- Same Region Replication (SRR)
- Cross Region Replication (CRR)

Example:

```
Bucket A (Mumbai)
        │
Replication
        │
Bucket B (Singapore)
```

Use Cases:

- Disaster Recovery.
- Compliance.
- Low latency access.

Versioning must be enabled on both buckets.

---

# 7. Storage Classes

Amazon S3 offers different storage classes based on cost, availability, and access frequency.

| Storage Class | Best For |
|---------------|----------|
| S3 Standard | Frequently accessed data |
| S3 Intelligent-Tiering | Unknown access patterns |
| S3 Standard-IA | Infrequently accessed data |
| S3 One Zone-IA | Non-critical infrequent data |
| S3 Glacier Instant Retrieval | Archived data with quick access |
| S3 Glacier Flexible Retrieval | Long-term archives |
| S3 Glacier Deep Archive | Lowest-cost long-term storage |

Choose the storage class based on how often data is accessed.

---

# 8. Lifecycle Rules

Lifecycle Rules automatically manage objects during their lifetime.

They can:

- Move objects to cheaper storage classes.
- Delete old objects.

Example:

```
After 30 Days
↓

Move to Standard-IA

↓

After 180 Days

↓

Move to Glacier

↓

After 365 Days

↓

Delete Object
```

Benefits:

- Reduce storage costs.
- Automate data management.

---

# 9. Object Encryption

Encryption protects data stored in S3.

Types of encryption:

### SSE-S3

AWS manages the encryption keys.

---

### SSE-KMS

AWS Key Management Service (KMS) manages encryption keys.

Provides better auditing and access control.

---

### SSE-C

Customer provides the encryption key during upload.

---

### Client-Side Encryption

The application encrypts data before uploading it to S3.

---

# 10. Pre-Signed URL

A Pre-Signed URL allows temporary access to a private S3 object.

Example:

A user needs to download a private PDF.

Instead of making the bucket public, generate a Pre-Signed URL valid for 15 minutes.

Advantages:

- Temporary access.
- Secure file sharing.
- No need to make the bucket public.

---

# 11. Practical

## Objective

Create an S3 bucket, upload objects, enable Versioning, and generate a Pre-Signed URL.

---

## Prerequisites

- AWS Account
- IAM User with S3 permissions

---

## Steps

### Create a Bucket

1. Open the AWS Console.
2. Navigate to Amazon S3.
3. Click **Create Bucket**.
4. Enter a globally unique bucket name.
5. Choose the AWS Region.
6. Create the bucket.

---

### Upload an Object

1. Open the bucket.
2. Click **Upload**.
3. Select a file.
4. Upload the object.

---

### Enable Versioning

1. Open the bucket.
2. Select **Properties**.
3. Enable **Bucket Versioning**.

---

### Create a Lifecycle Rule

1. Open the bucket.
2. Select **Management**.
3. Create a Lifecycle Rule.
4. Define transition or expiration settings.

---

### Generate a Pre-Signed URL

1. Select the uploaded object.
2. Choose **Share with a Pre-Signed URL** (or use AWS CLI/SDK).
3. Specify the expiration time.
4. Copy the generated URL.

---

## Verification

- Upload multiple versions of the same file and verify Versioning.
- Access the object using the Pre-Signed URL.
- Confirm Lifecycle Rules are configured correctly.

---

## Expected Outcome

- Successfully created an S3 bucket.
- Uploaded objects.
- Enabled Versioning.
- Configured Lifecycle Rules.
- Generated a working Pre-Signed URL.

# 12. Extra Topics

## 12.1 S3 Access Control (IAM vs Bucket Policy vs ACL)

| Method | Purpose |
|---------|---------|
| IAM Policy | Controls what IAM users, groups, and roles can access |
| Bucket Policy | Controls access to a specific bucket |
| ACL (Access Control List) | Legacy permission mechanism for buckets and objects |

**Note:** AWS recommends using IAM Policies and Bucket Policies instead of ACLs.

---

## 12.2 Static Website Hosting

Amazon S3 can host static websites containing:

- HTML
- CSS
- JavaScript
- Images

It cannot run server-side code such as Java or PHP.

---

## 12.3 S3 Event Notifications

S3 can trigger actions when events occur.

Examples:

- Upload a file → Trigger AWS Lambda.
- Upload an image → Resize it automatically.
- Upload a document → Send an SNS notification.

Supported destinations:

- Lambda
- SNS
- SQS

---

## 12.4 Multipart Upload

Large files are divided into smaller parts and uploaded in parallel.

Advantages:

- Faster uploads.
- Resume failed uploads.
- Better performance for large files.

Recommended for files larger than 100 MB and required for objects larger than 5 GB.

---

## 12.5 Transfer Acceleration

S3 Transfer Acceleration speeds up uploads and downloads by routing traffic through AWS Edge Locations.

Useful when users upload files from distant geographic locations.

---

# 13. Interview Questions

### Q1. What is Amazon S3?

Amazon S3 is a highly durable and scalable object storage service used to store and retrieve data.

---

### Q2. What is the difference between a Bucket and an Object?

A Bucket is a container, while an Object is the actual file stored inside the bucket.

---

### Q3. Why is Versioning used?

Versioning protects against accidental deletion and allows recovery of previous object versions.

---

### Q4. What is the difference between SRR and CRR?

- SRR replicates data within the same AWS Region.
- CRR replicates data to another AWS Region.

---

### Q5. What is a Pre-Signed URL?

A temporary URL that allows secure access to a private S3 object for a limited time.

---

### Q6. Which storage class is the cheapest for long-term archival?

S3 Glacier Deep Archive.

---

# 14. Summary

- Amazon S3 is an object storage service designed for scalability, durability, and availability.
- Data is stored as Objects inside Buckets.
- Bucket Policies control access to buckets.
- Versioning protects against accidental deletion and overwrites.
- Replication improves availability and disaster recovery.
- Storage Classes optimize storage costs.
- Lifecycle Rules automate object transitions and deletions.
- Encryption secures data at rest.
- Pre-Signed URLs provide temporary, secure access to private objects.
